# 自检脚本

改完 `public/` 或 `src/` 之后，跑这两个脚本可以确认没有被改坏。

原理：用 CDP（Chrome DevTools Protocol）驱动真实的 Edge 浏览器加载页面，
在真渲染环境里跑断言、量几何尺寸、抓控制台报错。**不引入任何依赖**（Node 22 自带 `WebSocket`）。

## 跑之前

**别直接对着正在用的那份数据跑。** 脚本会点按钮、编辑经历、保存复盘，全都是真实写入。

`store.js` 里的 `DATA_DIR` 写死成 `path.join(ROOT, 'data')`，**没有环境变量可以切**——
所以"另起一个服务实例"（端口 8777 被占会自动落到 8778）看着像隔离，其实**写的还是同一份数据**。
正确做法是复制一份项目副本，在副本里跑：

```powershell
$repo = (Get-Location).Path                   # 在仓库根目录执行
$box  = Join-Path $env:TEMP "wb-qa-sandbox"
Remove-Item $box -Recurse -Force -ErrorAction SilentlyContinue
Copy-Item $repo $box -Recurse -Force
Set-Location $box; node server.js             # 8777 被占，会自动落到 8778
```

然后另开一个窗口，用 `WB_BASE` 把脚本指到副本：

```powershell
Set-Location (Join-Path $env:TEMP "wb-qa-sandbox\qa")
$env:WB_BASE = "http://127.0.0.1:8778"
node check-func.js
```

验完把沙箱停掉、目录删掉即可，真实数据全程零改动。

> 只想确认"服务是不是活着"这种轻量检查，直接打 `http://127.0.0.1:8777/api/state` 就够了，不必跑脚本。

## 跑

```bash
cd qa
node check-func.js    # 155 项功能 / 交互断言，顺带截图
node check-resp.js    # 121 项响应式断言，6 个宽度 × 8 个视图 + 竞赛库弹窗
```

结果写在 `qa/out/`：`wb-qa.txt`、`wb-resp.txt` 是断言清单，`q-*.png` 是截图。

末行是 `=== 控制台报错 (N) ===`，**N 必须是 0**。

## 数据夹具（脚本自己备料）

断言量的是「有内容时」的排版与几何——时间轴、抽屉、导出分页、材料卡、照片落位。
空库上这些会直接量到 `null`，所以在开跑前脚本会自己把夹具备齐（`check-func.js` 开头那段）：

| 补什么 | 只在什么情况下补 |
| --- | --- |
| 示例经历（`/api/demo/load`） | 库里没有 `demo-lanqiao` 时 |
| 个人资料（学校/学院/年级/GPA/排名/英语） | 这些字段为空时 |
| 证件照（现场生成 1×1 PNG） | `profile.photo` 为空时 |
| 材料（png / docx / pdf 三种） | 库里没有「带真实文件、能预览」的材料时 |

**只填空缺，不覆盖**——所以脚本也能安全地跑在已有真实数据的库上（仍建议用沙箱，见上）。
补进去的东西会如实列在结果文件里，形如：

```
fixture {"loaded":true,"exp":5,"filled":["name","school",...],"photo":true,"mats":3}
```

有些断言需要「当前数据集恰好长成某个样子」才观察得到，例如
**「空成果的类型只是没得勾，没有藏起来」得库里真有空类型**。
这种情况报 `SKIP` 并写清原因，**不算失败**——它说明没验到，不说明功能坏了。
结果文件里 `SKIP` 单独成段；`PASS` 与 `SKIP` 都不该有 `FAIL`。

**设置页只剩两块（提醒/经历类型），竞赛库与数据与外观整块删除，被删说明文案（关机补发/SMTP 落盘/库来历）的回归哨兵** /
**简历导出：3 口径（保研/求职/出国，自定义已删）、出国锁定英文、照片选项按口径默认（出国不放）、

## check-resp.js 覆盖什么

在 1400 / 1240 / 1000 / 820 / 640 / 420 六个宽度下，逐个视图检查：
有没有元素越出视口、看板列数是否符合断点、时间轴在窄屏下是否还对得齐、
**每个月份标签是否都还落在竖线左边**、导出页 4 种格式下左栏是否都装得下、
**预览区「适应」在每种宽度下都真的把整张纸放进框里**、
**竞赛库弹窗（搜索框 + 档次下拉 + 按钮挤成一排）是否装得下**、
侧栏是否正确塌缩成底部导航且不遮住内容。

## 写断言的两条纪律

1. **别把像素写死。** 竖线位置要从 `getComputedStyle(el, '::before').left` 实读。
   曾经因为脚本里写死 `+66`，改了一次栅格后三条断言全误报。
2. **要量"最难的那个"。** 月份标签最初只量了第一个月份（「9 月」）就通过了，
   而「10 月」更宽——改成遍历所有月份取最窄气口，才抓出窄屏下的重叠。

## 环境变量

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| `WB_BASE` | 服务地址 | `http://127.0.0.1:8777` |
| `WB_OUT` | 结果输出目录 | `qa/out` |
| `WB_BROWSER` | 浏览器可执行文件 | 自动找 Edge |
| `WB_CDP_PORT` | 调试端口 | 9333 / 9334 |

## 写断言的第三条纪律

3. **不要在 Node 侧引用浏览器里的变量**（比如 `S`）。它只活在页面里，写成
   `assert(..., NP.grade === (S.profile.grade || ''))` 会直接 `ReferenceError`，
   而且会把**整份结果文件覆盖成一行 `ERROR:`** —— 读起来像"0 项断言"，很容易误判成脚本没跑。
   要比较的量一律在 `cdp.eval` 内部算完再 `return`。

## 写断言的第四条纪律

4. **用户要用鼠标点的东西，断言就得真点。** 不能图省事直接调 `openXxx()`。

   踩过的坑：右上角那排按钮（提醒预览 / 新增经历 / 从竞赛库添加 / 导出到文件）渲染在
   `#topbarActions` 里，而它在 `<header>` 中、**`#view` 外面**；`bindView()` 只绑 `#view`
   内的元素，于是那排按钮**一个都没绑上事件，点上去毫无反应**。
   而当时所有弹窗断言都是 `openLibraryModal()` / `openChanges()` 直接调函数，
   页面照样渲染得出来 —— **一条断言都没红**。

   现在这组断言是这么写的：先断言每个按钮 `typeof el.onclick === 'function'`，
   再挑两个安全的按钮（提醒预览、去经历里添加）真 `b.click()` 一次，看弹窗开没开、视图切没切。
   有副作用的按钮（立即检查一次、导出到文件）只查 handler 存在，不真点。

## 写断言的第五条纪律

5. **断言别绑实现细节，要绑用户看得见的东西。**

   踩过的坑：缩放断言原本读 `stage.style.transform`（当时 scale 加在 stage 上）。
   后来把 scale 挪到 iframe（stage 改当占位盒）——功能更好，`transform` 却成了空串，
   断言当场变红，而**用户看到的百分比标签一切正常**。改成读 `#zoomPct` 的文本后立刻转绿。

   同理，"整页装得下"要量 `getBoundingClientRect()`（可见矩形），
   不是 `offsetHeight`（布局尺寸）——缩放场景下两者本来就该差一个比例。

## 截图和断言各管一半

**两条腿走路，缺一不可：**

- **几何量断言**保证"不出错"——重叠、溢出、对不齐、报错。这类问题肉眼扫图容易漏。
- **肉眼看截图**发现"不好看 / 文案自相矛盾 / 语义错"。这类问题**没有任何几何断言能抓到**，
  实际抓到的三个例子：侧栏高亮一直停在「概览」、就绪度 60% 却写"五项都齐了"、月份标签被竖线穿过。
- 反过来也成立：**别看着缩略图猜数值**。曾经目测进度条只填了约 36%，断言一量是 `289/481 = 60%`，
  差点去"修"一个不存在的 bug。**有疑问就写断言量，不要猜。**

新加视觉细节时，两件事都要做：补一条几何断言，并且真的把 `qa/out/q-*.png` 打开看一眼。

## 修过的坑：续页标题的后缀累积

某章连跨多页时，续页会把上一页的标题整个克隆过来、再拼一个「（续）」。
第二页的标题已经带了后缀，第三页克隆它就成了「…（续）（续）」，往后越滚越多——
把一节撑到 46 条实测过，第八页挂着六个「（续）」。

修法是给克隆出来的续页标题打一个 `data-cont` 标记，拼后缀前先看有没有：
有就说明它自己已经是续页标题了，直接沿用。这样跨多少页，后缀都只有一层。

复现和验收都在 `probe-cont.js` 里（把首页某节的条目复制几十份撑成超长节，
手动触发 `window.__paginate()`，再把每页的 `h2` 读出来数后缀）：

```bash
WB_BASE=http://127.0.0.1:8777 node qa/probe-cont.js
```

只读页面、不写数据，可以直接对着真实实例跑。

## 设计取舍：双栏 / 侧栏版式不做屏幕分页

分页脚本开头有一句 `if (sheet.querySelector('.cols')) return false;`——整张纸是一个 flex 容器时直接放弃拆页。
原因是那几种版式的左右两栏是整体涂色的，按条目拆开会把版式拆散。

后果要说清楚：**compact / sidebar 在屏幕预览里就是一张长纸**（页码显示 1 / 1），
真实页数由打印或导出 PDF 时浏览器的分页兜底，只有在纸面上才对。
单栏版式（classic / plain / academic / elegant / dense…）是逐条精确拆页的，屏幕所见即打印所得。

自检里的分页断言量的是「分页机制」本身，所以会先把版式切到单栏再量、量完换回去——
否则会被上一条用例留下的双栏选择带偏，量出一张没拆的长纸来（这是真踩过的坑）。

## 已知限制：同一张纸连拆两次时页序会乱

分页是一轮一轮来的：搬走一批之后这张纸还是放不下，就再拆一次、新页插在这张纸紧后面。
问题就在这里——**第二次拆出的页会插到第一次拆出的页前面**，
于是本该跟着这张纸的后续章节，反而跑到了续页后头。

触发条件是「一张纸上有多个节，且第一节拆完条目后本页仍超限」，
也就是某一节的条目多到离谱（那节 46 条时才复现，真实简历不会长这样）。

试过让第二次拆出的内容接着往同一张溢出页里倒，结果更乱（后续章节全被追加到那批续页之后），
已回滚。这一版不动分页算法，先记在这里。

## 修过的坑：判据要量「外边距盒子」的底边

`getBoundingClientRect().bottom` 不含 `margin-bottom`，而外边距在纸上照样占高度。
于是出现这种情形：整段的底边 1066px、可用到 1070px，看着装得下，`scrollHeight` 却是 1131px——
超出的 8px 就是最后一条的 3.1mm 外边距。

它还躲过了兜底：兜底那条要求「本页至少两个子元素」，而这时整张纸只剩一个 `section`，
挪走就空了，于是放弃拆分、把溢出留在纸上（实测第 4 页，单栏、6 页稿子）。

现在找越界元素和找切点都用 `outerBottom()`（`bottom` + `margin-bottom`），量的是外边距盒子。

## 修过的坑：分页判据那 1px 容差

`PAGINATE_JS` 里挑「该挪到下一页的那一段」用的是 `bottomIn(el) > limit + 1`。
那个 `+1` 是当初为防亚像素误差留的容差，代价是：**底边正好落在 `limit + 1` 上的那一段会被放过**。
而它后面还压着看不见的高度（末条的外边距、行盒之类不会反映在 `bottom` 里），
于是整张纸顶出去十几像素——实测首页 1135px / 可用 1123px，溢出 12px。

定位办法值得记一笔：把「学制年份 / GPA / 排名 / 英语」清空、教育背景只剩一行，
4 张纸全是 1123px 整；加回去就冒出来——变量只有一个，一次对照实验就锁定了触发条件。
再把那张纸的 `boxSizing / padding / limit / 每个子元素的 bottom 与 margin` 全量出来，
就看到 `bottom = 1071` 和 `limit = 1070` 顶在同一根线上。

现在判据就是 `> limit`，另补一条兜底：**纸确实超了、却没有任何子元素越过 limit 时，
把最后一个子元素整体挪走**——这种情况只看子元素底边永远逮不到。
